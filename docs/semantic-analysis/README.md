# 实验三 · 语义分析与四元式生成

## 使用方法

在仓库根目录使用 Linux、GCC 和 GNU Make 构建、测试并运行样例。

```sh
make all test
./build/compiler docs/semantic-analysis/results/example.c --all-tokens
cat docs/semantic-analysis/results/quadruples.txt
```

`--all-tokens` 可省略。成功时，终端与结果文件按相同顺序列出四元式。结果文件通过同目录临时文件写入，完整关闭后原子替换。分析、IR 生成或文件替换失败时，保留最近一次成功的结果文件。`make clean` 可清除这一运行产物。

[完整源程序](results/example.c) · [实测四元式快照](results/example-ir.txt)

## 双遍解析

1. Lexer 写入 `TokenBuffer`。`PARSE_CHECK` 使用递归下降检查语法、构建符号表并检查声明及确定初始化。`if/else` 合流取分支初始化状态的交集，循环退出恢复入口状态，`for` 的初始化表达式在入口状态中保留。
2. 语法和语义通过后，以 `PARSE_IR` 从头解析同一份 Token，按符号表下标生成变量操作数。IR 遍跳过检查遍专用的符号写入、初始化状态更新和语义诊断。
3. 生成结束后验证标签定义和跳转目标。IR 遍失败时恢复进入该遍前的四元式条目数、指令数、临时变量计数、标签条目数和下一个标签编号。已分配的表容量可在后续尝试中复用。

## 四元式与控制流

每行格式为 `序号 (op, opr1, opr2, result)`。`_` 表示空操作数，变量显示源名称，立即数显示十进制，临时变量和标签分别从 `t0` 和 `L0` 开始编号。关系运算 `>`、`<`、`>=`、`<=`、`==`、`!=` 使用两侧算术表达式的结果，产生一个值为 `0` 或 `1` 的布尔临时变量。

| 结构 | 四元式顺序 |
| --- | --- |
| `if` | 条件 → `brf` 跳向结束 → then → 结束标签 |
| `if/else` | 条件 → `brf` 跳向 else → then → `br` 跳向结束 → else 标签 → else → 结束标签 |
| `while` | 条件入口标签 → 条件 → `brf` 跳向退出 → 循环体 → `br` 跳回条件入口 → 退出标签 |
| `for` | 初始化 → 条件入口标签 → 条件 → `brf` 跳向退出 → 循环体 → 更新 → `br` 跳回条件入口 → 退出标签 |

标签编号在生成跳转前分配，前向跳转直接引用该编号，生成结束时校验每个编号都恰好定义一次。`br` 无条件跳转，`brt` 在条件非零时跳转，`brf` 在条件为零时跳转。当前 Parser 使用 `brf` 让真分支顺序执行。`for` 更新表达式预解析只消费 Token，循环体之后重新解析并生成一次 IR。悬挂 `else` 与最近的未匹配 `if` 结合。

## 自测结果

`make all test` 全量构建通过，无编译警告，共 64 项检查。

| 测试 | 通过 | 验证内容 |
| --- | ---: | --- |
| Parser | 15 | 表达式文法和两种模式的首个语法错误 |
| 语义 | 20 | 声明、初始化、分支及循环状态、双遍一致性 |
| 临时变量及标签 | 6 | 编号、三种跳转、无效或重复标签、容量耗尽与回滚 |
| 表达式及控制流 IR | 17 | 算术优先级、赋值与读写、六种关系、真假分支布局、嵌套控制流、整数边界及回滚 |
| CLI 端到端 | 6 | 样例的终端与文件输出、词法/语法/语义/IR 失败、结果文件替换失败 |

另在临时测试中注入了语义状态分配失败和已生成标签后的 IR 表扩容失败，核对了资源错误状态、已有 IR 保留、全部计数器回滚和重试成功。

## 范围与限制

- 沿用实验二文法。程序由一个带顶层声明的块组成，类型为 `int`，条件由一个关系运算符和两个算术表达式组成。`for` 的初始化、条件和更新均为必填。
- 源代码字面量为十进制无符号整数词法形式，生成 IR 时须能表示为宿主 `int`。运行时算术行为留给后续执行阶段，实验三交付范围止于四元式。
- 单次编译最多容纳 32768 个 Token 和 32768 条 IR 表记录，标签也占一条记录。输出路径相对于当前工作目录。
